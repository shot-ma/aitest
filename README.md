# aitest

サイボウズOfficeのカスタムアプリのような、項目を自由に定義できるデータベースツール。

## 機能
- アプリの作成・編集・削除（空のアプリ、またはテンプレート: 顧客名簿 / 問い合わせ管理 / 備品管理）
- 項目の定義（追加・削除・並び替え・必須指定）
  - 文字列（1行/複数行）、数値、日付、時刻、メニュー、ラジオボタン、チェックボックス（複数選択）、チェック（オン/オフ）、URL
- レコードの登録・編集・削除（項目タイプに応じた入力チェック）
- 一覧のキーワード検索、選択項目での絞り込み、並び替え、ページ送り
- カレンダー表示: 日付項目を持つアプリに「カレンダー」タブが出る。月ごとにレコードを表示し、
  クリックで編集画面を開ける。カレンダーに出す項目（表示項目）は画面上で切り替えられる。日付の「＋」からその日付を入れた状態でレコードを追加できる
- ビュー: 一覧（表形式）またはカレンダーの表示設定に名前を付けて保存し、切り替えて使える
  - 一覧: 表示する項目、並び順、絞り込み条件 ／ カレンダー: 基準の日付項目、表示する項目、絞り込み条件
  - ビューごとに使える人を指定できる（アプリを見られる全員 / 指定したユーザーだけ）
  - 先頭のビューが全員共通の既定になり、アプリを開くと最初に表示される
  - 保存・編集・削除はアプリの管理権限を持つ人が行う。全項目を出す標準の一覧とカレンダーは常に選べる
  - ビューの公開範囲は「そのビューを選べるか」の設定。項目そのものを隠すには下の「項目ごとの閲覧権限」を使う
- 項目ごとの閲覧権限: 項目ごとに「閲覧できる人」を指定できる（アプリを見られる全員 / 指定したユーザーだけ）
  - 制限した項目は、指定した人とアプリの管理権限を持つ人以外には存在しないものとして扱う。
    一覧・レコード画面・カレンダー・ビューのほか、検索・絞り込み・並び替え・集計・CSV・添付ファイルの
    ダウンロード・他アプリからの参照でも値を返さない（サーバー側で除外）
  - 閲覧できない項目は編集もできない
- 項目ごとの編集権限: 項目ごとに「編集できる人」を指定できる（閲覧できる編集者全員 / 指定したユーザーだけ）
  - 制限した項目は、指定した人とアプリの管理権限を持つ人以外は値を見られるが変更できない（閲覧のみ）
  - 変更できない項目は、その人がレコードを更新しても値が保たれ、新規登録・CSV 取り込みでは
    空のまま登録される（必須項目でもエラーにしない）。閲覧できない項目も同じ扱い
- 集計（項目の値ごとの件数、数値項目の合計）
- CSV 書き出し（BOM 付き UTF-8）／取り込み（UTF-8・Shift_JIS、1行目の項目名で照合）
- コメント: レコードごとにコメントを投稿・削除（削除は自分のコメント、またはアプリの管理権限を持つ人）。
  ファイルを添付できる（1コメント 10 件まで、1ファイル 10MB まで。添付だけのコメントも可）
- ダッシュボード: ログイン後のホームに、横 5 × 縦 10 のマス目でビューを自由に配置できる
  - 置けるのは、使える保存済みビューと、各アプリ標準の一覧・カレンダー。位置と大きさ（幅・高さのマス数）を指定する
  - 配置はユーザーごとに保存される。変更していない人には、システム管理者が決めた「全員の既定」が表示される
  - 「既定に戻す」で自分用の配置を消せる。見る権限のないビューや削除されたビューは表示されない
- 添付ファイル: 項目タイプ「添付ファイル」（1ファイル 10MB、1項目 10 件まで。`data/uploads/` に保存）
- アプリ間のデータ参照: 項目タイプ「他アプリのレコード参照」（参照先アプリと表示する項目を指定。
  参照先の値を変更すると表示も追従し、クリックで参照先レコードを開ける）
- 通知: アプリごとに「通知を受け取る」を押すと、レコードの登録・更新・削除・コメントが
  画面右上のベルに届く（アプリの作成者は最初から受け取る。レコードの作成者と、
  そのレコードにコメントした人にも届く）。メール等の外部通知はありません
- ログインと権限管理（下記）

## ログインと権限
- 初回アクセス時に「初期設定」画面が出ます。ここで登録した最初のユーザーが**システム管理者**になります
- 以降のユーザーは、システム管理者が右上のアカウントメニュー →「ユーザー管理」から追加します
  （自分で新規登録する画面はありません）。無効化・パスワード再設定・管理者の変更もここで行います
- 各自、アカウントメニューから表示名とパスワードを変更できます

アプリごとの権限は、アプリの「設定」→「アクセス権」で決めます。

| 権限 | できること |
| --- | --- |
| 閲覧のみ | レコード・コメント・添付ファイルの閲覧、集計、CSV 書き出し、通知の受け取り |
| 編集可 | 上記に加えて、レコードの登録・編集・削除、コメント、CSV 取り込み |
| 管理 | 上記に加えて、項目とアクセス権の設定、アプリの編集・削除 |

- 「全ユーザー」向けの権限（アクセス不可 / 閲覧のみ / 編集可）と、ユーザーごとの個別指定を組み合わせます。
  両方ある場合は強い方が有効です
- 新しいアプリは「全ユーザー: 編集可」で始まり、作成者が管理権限を持ちます。アプリは誰でも作成できます
- アクセス不可のアプリは一覧に出ず、URL を直接開いても存在しないものとして扱われます
- システム管理者は、すべてのアプリを管理できます
- 参照項目は、参照先アプリを閲覧できない人には内容を表示しません（「権限なし」と表示）

### セキュリティ上の仕様
- パスワードは scrypt（パスワード用のハッシュ関数）でハッシュ化して保存します
- ログイン状態は Cookie（HttpOnly・SameSite=Lax）で 14 日間保持します。
  HTTPS で公開する場合は環境変数 `COOKIE_SECURE=1` を設定してください
- 同じユーザーIDで 5 回続けてログインに失敗すると、1 分間ログインできなくなります
- 他サイトからの書き込みリクエストは拒否します（CSRF 対策）

## 構成
- Python + FastAPI（`app/main.py`）
- SQLite（`data/app.db`、レコードの値は JSON で保存）。旧バージョンの DB は起動時に自動で移行
  （ログイン導入前のアプリは「全ユーザー: 編集可」になり、当時の通知とフォロー設定は引き継がれません）
- 画面はビルド不要の HTML / CSS / JavaScript（`static/`）

## 起動
```bash
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```
ブラウザで http://localhost:8000 を開きます。API 仕様は http://localhost:8000/docs で確認できます。

## テスト
```bash
python -m pytest
```

## クラウド環境
- セットアップ: `scripts/setup.sh`
- 環境変数: `.env.example` を参照（`DATABASE_URL` で DB ファイルの場所を変更可能）
